# Algo with Minions

A responsive, front-end-only algorithms explorer with Sorting, Searching, Trees, Graphs, Dynamic Programming, Hashing, Optimization and Mathematics. The 61 menu entries cover all 63 demonstrations in the original course plan through shared tree operations, with several additional demonstrations. Open `index.html` in a modern browser, or serve this directory as a static website. No build, database or external assets are required. Array input and saved preferences remain in the browser.

Sorting: bubble, selection, insertion, merge, quick, heap, ordered-key counting, pancake and exhaustive sorting.

Searching: linear, sentinel, binary and ternary. Sentinel is clearly labelled as an extra beyond the course tutorials. Enter a target alongside the array. Searching supports up to 16 values, with explicit 8-, 12- and 16-value examples and an 8-value default whenever Searching is opened or the page is reloaded; larger arrays scroll within the animation on narrow screens and the viewport follows the active probe. Linear and sentinel return the first matching index; binary and ternary return any matching index. Ordered searches reject descending input; the explicit Sort input action is available before trying again. Sentinel search visibly installs and restores its temporary last-element value. Characters retain their original columns, candidates fade as they are eliminated, and a green outline confirms the returned index. Sorting hats are reserved for sorting.

Algorithms are selected from the Sorting, Searching, Trees and Graphs navigation menus; the active algorithm is highlighted there. There is no duplicate selector in the input panel. Every algorithm has a visible Custom input action. It pauses playback and focuses the appropriate editor while retaining the current data as a starting point. Sorting accepts an array; searching an array and target; trees an insertion order and operation key; graphs vertices, weighted edges and applicable settings. Apply starts the selected algorithm with the entered input.

The highlighted Python line follows every displayed execution step in both playback modes. A current-line strip in the sticky playback controls keeps that code visible while watching the animation, even when the full inspector is below the viewport. The code pane scrolls to the active line and repeated executions pulse during Quick Run (except with reduced motion).

Controls include one-second Quick Run/Pause toggles in both control bars, individual executed-line steps in both directions, restart, scoped live variables, call stacks and code-header playback and Reset buttons with instant descriptions that dismiss after three seconds. State history includes arrays, counters, recursion levels, temporary values and algorithm-confirmed final positions. Animation metadata is kept outside the displayed Python.

Numeric input supports finite JavaScript numbers, including negatives, zero, decimals and scientific notation. Plain integer literals outside the exact JavaScript integer range are rejected. Standard algorithms accept up to 10 values; exhaustive sort accepts up to 6. Empty arrays are supported. Ordered-key counting includes comparison-based key compression, so its displayed bound is O(n + k log k).

Trees: BSTs, AVL trees, 2–3 trees, and balanced multiway trees (orders 3–6). Each family supports search, insert, delete, construction, preorder, inorder and postorder. Enter an insertion order of up to 16 finite keys and an operation key; duplicates follow set semantics and are ignored. Each run starts from the configured insertion order. Construction starts from empty. Worked examples cover leaf/one-child/two-child deletion, all four AVL rotation patterns, and 2–3 split/merge cascades. Node references, child pointers, heights, temporary held nodes/keys, traversal output and call stacks are visible and reversible. Key characters retain identities as nodes rotate, successors move and promoted keys change boxes. Pan/zoom controls keep larger trees readable, and completion recentres the final tree.

The tree programs displayed in the Python panel are executed by a small browser-local interpreter for the trusted bundled programs. There is no Python server or arbitrary code execution input. Sources live in `tree-sources/`; regenerate their browser bundle with `npm run bundle:trees` after editing. The Python parity test verifies line execution and locals against actual Python. Multiway search is covered in the course; the balanced B-tree insertion/deletion implementation extends that demonstration.

Graphs: 13 course demonstrations grouped into traversal (BFS/DFS), source-removal topological ordering, Prim/Kruskal minimum spanning forests, Dijkstra, Warshall, Floyd–Warshall (course extension), Ford–Fulkerson with DFS paths, Edmonds–Karp with BFS paths, greedy colouring and local recolouring (tutorial extras), and exhaustive travelling-salesman search. All use the shared reversible Python controls, live variables, persistence, pause/resume, and completion effects.

Edit up to 12 named vertices and 60 edges, with optional direction and weights. Missing pairs have no edge; zero is a real weight. Weights may be negative or fractional (magnitude at most 1e9), except Dijkstra rejects negatives and flow requires integer capacities 0–1000. TSP is limited to 7 vertices to keep exhaustive traces usable; a one-vertex graph has a zero-length tour. Colouring rejects self-loops; directed cycles remain valid inputs for topological sort and demonstrate failure. Input errors preserve the current history. The graph input is expanded by default and shows the vertices and weighted edge list for every worked example. The example selector always offers Custom graph, which keeps the current values as an editable starting point and preserves custom mode through Apply, Reset and reload. The remaining entries contain only relevant, compatible examples for the selected algorithm. Example names survive Apply, Reset, reload and start/destination changes; only changes to vertices, edges, weights or direction make the graph custom. Whitespace and edge-list ordering do not change its identity. Algorithms with one required direction show a fixed Directed/Undirected label rather than an invalid toggle. Graphs allow isolated vertices, disconnected components, directed antiparallel edges and empty inputs. Duplicate edges are rejected explicitly. Flow uses net antisymmetric flow, so residual paths can cancel earlier choices even when both original directions exist.

The graph scene preserves vertex identities and displays current/visited/settled states, connecting edges, colours and reverse residual edges. Queues, recursion paths, traversal outputs, accepted edges, distances, transitive-closure/all-pairs/residual matrices and minimum-cut certificates follow the actual source variables. A zero-length path makes every Warshall diagonal true; Floyd–Warshall reports negative cycles and marks every affected pair undefined. Local recolouring explicitly reports a local minimum when no single recolouring improves the conflict count; this is not a proof of infeasibility. Neighbours and ties use vertex input order. Python uses 0-based indices, mapped to vertex labels above the scene.

Graph history shares frozen input arrays and unchanged frame values, reducing memory for longer traces without retaining mutable execution state.

Graph sources live in `graph-sources/` and use the same browser-local trusted Python interpreter as Trees. Run `npm run bundle:graphs` after editing them. No backend or network execution is used. The additional algorithm sources use that same trusted interpreter; no user-supplied code is evaluated.

Browser tests use Playwright. Install development tools with `npm install` and `npx playwright install chromium`, then serve the repository with `python3 -m http.server 4318`. In another terminal run `npm run test:ui`. You can override `PREVIEW_URL` and set `CHROME_PATH` to use a local Chrome executable. The app itself needs no dependencies. Test screenshots are local-only and ignored by Git.

GitHub Pages publishes the static files from the root of the main branch. Pushes to main update the hosted website. The illustrated characters are original SVG drawings; this project is an unofficial educational demo.

Additional course demonstrations:

- Dynamic Programming and Tables (9): memoised / bottom-up Fibonacci, Levenshtein edit distance, 0/1 knapsack, non-adjacent coin row, monotone grid-path counting with blocked cells, maximum/minimum grid-sum paths, 2D prefix sums with rectangle queries, and minimum-coin change.
- Hashing (5): separate chaining, linear probing, quadratic probing, double hashing, and rehashing with table growth. Operations support insertion, lookup and deletion; duplicate keys use set semantics, open addressing retains tombstones, and quadratic probe exhaustion is distinguished from a full table.
- Optimization (5): exhaustive 0/1 knapsack, greedy coin change, Huffman coding, earliest-finish interval scheduling, and Gale–Shapley stable matching. Greedy failure / suboptimality and proposer-optimal matching are explained. Huffman uses a visibly sorted-list queue, with its actual O(n² log n) bound.
- Mathematics (3): Euclid’s GCD, gradient descent on a configurable convex quadratic, and Newton–Raphson on a configurable quadratic / linear function. Numerical methods report convergence, iteration limits, divergence, and zero derivatives accurately.
- Searching additions (4): Quickselect with duplicate-aware ranks, bitonic-peak search, divide-and-conquer simultaneous min/max, and lighter-fake-coin search.
- Tree / heap additions (5): recursive height, direct balanced BST construction from sorted keys, max-heap insertion, extraction, and bottom-up construction. Heap construction and extraction are now independent demonstrations as well as phases of Heapsort.

Each addition has custom fields, relevant named worked examples, reversible exact source-line stepping, synchronized Quick Run/Pause and reset controls, live variables / call stacks, persistence, and an algorithm-specific scene. DP uses dependency / traceback tables; hashing shows bucket portraits and probe logs; tree / heap / Huffman scenes show actual links; matching is bipartite; scheduling uses a common time axis; numerical methods plot their actual recorded iterates. Empty and failure states are explicit. Inputs are bounded by the selected algorithm; integer-only domains reject decimal input instead of changing the mathematical problem. Values represent finite JavaScript numbers within the displayed educational limits.

Sources for these 31 additions are in `lab-sources/`; regenerate `lab-programs.js` with `npm run bundle:labs`. `lab-engine.js` owns schema validation and immutable snapshots, while `lab-renderer.js` and `lab.css` own the scenes and input UI styling. Existing algorithm engines are unchanged.

`course-coverage.json` maps the 63 original Week 4–12 plan rows to menu entries and tree operations. `tests/course-coverage.test.cjs` verifies every row resolves. `tests/lab-engine.test.cjs` checks independent exhaustive, shortest-path, stability, optimality and structure oracles across the additions. `tests/lab-python-parity.test.cjs` checks every line, local and call stack against actual Python for all worked examples, allowing normal floating-point rounding tolerance. `tests/lab-ui.test.mjs` checks desktop and touch flows, custom fields, invalid-input preservation, examples, playback, reload/reset and eight-menu containment. Quick Run tests cover all 61 menu entries.

DP solution reconstruction uses a cell-attached Minion that starts at the answer cell and jumps along the actual traceback route. Edit distance, grid-sum paths, knapsack, coin row and minimum-coin change retain immutable cursor positions and visited-cell trails in their execution snapshots. Diagonal coordinate updates do not create spurious sideways steps. Quick Run exposes each move, Back restores the earlier cursor and trail, reset clears the marker, and reduced motion places it directly in the next cell. Table values remain readable beside the actor, and the scene follows the active cell on narrow screens. Counting-only DP methods and unreachable solutions do not fabricate a traceback.

The shared SVG logo includes a small mascot hopping between its three connected nodes. The 4.8-second loop pauses on hover or keyboard focus; reduced-motion preferences keep the mascot stationary. The inline header artwork and downloadable dark/light SVG variants share the same motion and proportions.
